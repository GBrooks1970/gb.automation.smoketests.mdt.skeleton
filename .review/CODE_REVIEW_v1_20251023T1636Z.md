## Risks & Refactors (Highest → Lowest)

1) Hardcoded credentials and emails committed to repo
- Issue: Multiple passwords and emails in fixture (`smoketests.cypress.MDT.skeleton.v1/cypress/fixtures/env-data.json:28, 36, 43, 50, 57, ...`). This is a critical leak risk, even for test accounts.
- Refactor:
  - Move secrets to `cypress.env.json` (ignored by VCS) or environment variables. Only keep non-sensitive defaults in fixtures.
  - Parameterize user credentials via `CYPRESS_...` env vars and read with `Cypress.env('...')`.
  - Redact/rotate committed credentials. Add a secure secrets provider (e.g., CI secrets) for pipelines.

2) Suppressing all uncaught exceptions globally
- Issue: Returning false in `Cypress.on('uncaught:exception')` masks legitimate app regressions (`smoketests.cypress.MDT.skeleton.v1/cypress/support/e2e.ts:24`).
- Refactor:
  - Narrow the handler: only ignore known, documented benign exceptions (match by message/source).
  - Prefer targeted `cy.on('uncaught:exception', …)` within specific tests when unavoidable.

3) Test results XMLs committed; results not ignored
- Issue: Large number of `results/my-test-output-*.xml` files are checked in; repository bloat and noise.
- Refactor:
  - Add `smoketests.cypress.MDT.skeleton.v1/results/` to `.gitignore`.
  - Clean repository history or remove tracked results with a one-time cleanup PR.

4) cypress-wait-until not globally registered
- Issue: Custom commands use `cy.waitUntil` but the plugin is not imported in support (`smoketests.cypress.MDT.skeleton.v1/cypress/support/commands.ts:37, 46`) while a step file imports it ad hoc.
- Refactor:
  - Add `import 'cypress-wait-until';` to `smoketests.cypress.MDT.skeleton.v1/cypress/support/e2e.ts` to ensure availability for commands and tests.
  - Remove scattered per-step imports to avoid order dependencies.

5) Misconfigured/duplicated reporter configuration
- Issue: Reporter defined in `cypress.config.ts` (`reporter: 'junit'`, `mochaFile`) and redundantly set in `cy:merge-reports`. The script includes a stray `\\` argument that likely breaks the command (`smoketests.cypress.MDT.skeleton.v1/package.json:9`).
- Refactor:
  - Rely on `cypress.config.ts` for reporter config only; simplify scripts to `cypress run`.
  - Remove the stray backslash. If you do need a special run, prefer `cypress run --config-file cypress.config.ts` and pass env only.

6) Mixed ESM/CommonJS in Cypress config
- Issue: `cypress.config.ts` mixes `import` with `require` (`smoketests.cypress.MDT.skeleton.v1/cypress.config.ts:6`). This works but is inconsistent and can cause friction as tooling evolves.
- Refactor:
  - Standardize on ESM imports in TS. Example: `import { polyfillNode } from 'esbuild-plugin-polyfill-node';`
  - Consider `moduleResolution: "NodeNext"` if you fully embrace ESM across the project.

7) Batch scripts reliance on deprecated WMIC
- Issue: `wmic` is deprecated on newer Windows; date formatting may break over time (`smoketests.cypress.MDT.skeleton.v1/RUN_cy_DEBUGTEST.bat`, `smoketests.cypress.MDT.skeleton.v1/RUN_cy_DATAMAPPER.bat`).
- Refactor:
  - Replace with PowerShell-compatible timestamp generation or a small Node script. Alternatively, write to a `logs/` folder with a simple ISO date via Node.

8) Global exception handler + global polyfill may hide genuine problems
- Issue: The global `crypto` polyfill and all-exception suppression together risk hiding subtle failures (`smoketests.cypress.MDT.skeleton.v1/cypress.config.ts:19`, `smoketests.cypress.MDT.skeleton.v1/cypress/support/e2e.ts:24`).
- Refactor:
  - Justify and document the need for crypto polyfill. If used for specific steps, consider localizing polyfills or shims.
  - Tighten exception handling as per item 2.

9) Unused or type-only imports in commands
- Issue: Unused imports from Cypress types in runtime code (`smoketests.cypress.MDT.skeleton.v1/cypress/support/commands.ts:3–4`).
- Refactor:
  - Remove `import Bluebird...` and `import { isElement }...` or convert to `import type` if truly needed for types only.
  - Consider enabling `noUnusedLocals` in `tsconfig.json` for stricter hygiene.

10) Repeated tag scripts and duplicate batch wrappers
- Issue: Many near-identical scripts (`smoketests.cypress.MDT.skeleton.v1/package.json:10–15`) and batch files doing the same with different tags.
- Refactor:
  - Replace with a single parameterized npm script: `"cy:tag": "cypress run --env tags=\"$TAG\""` and pass `TAG=...` or use `npm run cy:tag -- --env tags=\"@DEBUGTEST\"`.
  - Provide one generalized batch script that accepts `%1` as the tag.

11) Potentially brittle base URLs and HTTP endpoint
- Issue: Hardcoded environment endpoints, including an HTTP internal URL (`topazURL`) in fixtures (`smoketests.cypress.MDT.skeleton.v1/cypress/fixtures/env-data.json:13`). Changing environments requires code/fixture edits and exposes internal infra details.
- Refactor:
  - Externalize base URLs via CI/CD env or `cypress.env.json` with per-env overlays.
  - Keep fixtures for non-sensitive paths; compose full URLs at runtime from `Cypress.env()`.

12) Global mutable “scenario context” in config env
- Issue: `config.env.globalTestData` is set in plugin (`smoketests.cypress.MDT.skeleton.v1/cypress.config.ts:25–28`). Global mutable state across tests can cause cross-test interference if not carefully reset.
- Refactor:
  - Initialize context per spec or in `beforeEach`, and clear after tests that mutate shared state.
  - Provide helper to safely create and tear down scenario contexts.
